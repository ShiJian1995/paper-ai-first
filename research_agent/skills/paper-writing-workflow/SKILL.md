# 论文写作

先确定用户交付目标、稿件语言、编辑范围和已有输入。可从任一行开始；同一请求有多项任务时按依赖顺序交接。输出实质工作，只有用户要求计划时才止于列步骤。子技能由当前助手按需读取并执行，无需并发代理。

## 定位论文

- 在含 `paper.py` 的论文工作区，先运行 `python paper.py list`，读取项目的 `research-orchestrator` 以及 AGENTS.md。选定 ID 后运行 `python paper.py --paper <id> next`，读取对应阶段产物。多个合理目标时询问一次。前者负责阶段状态，本技能负责当次写作任务；同一任务只进入本路由一次。
- 区分项目阶段与本次交付。仅修改给定段落、查几条引文或回复一条意见时，局部完成，不自动定题、创建论文或推进阶段。独立稿件可直接以用户给出的文件或文本为输入。
- 正式定题和转入实验遵守项目的全文数量、分层核验、趋势时效及数据可得性要求，包括项目对特定论文的附加门槛。来源优先级、全文定位和独立研究计数分别记录。只处理当前论文的材料。

## 写作中的作者决策

当作者要求在一次完整写作中积累关键决策时，从该次对话起执行以下步骤，恢复工作时先读本论文的决策记录。

1. 在作者作出或修正实质选择的当轮，把决定应用到当前交付。选择会改变研究范围、证据取舍、比较口径、实验设计、行文组织或审稿回复时，记入本论文的 `research/decisions.md`。每项写明阶段、决定、适用范围及影响的产物。理由仅在作者给出时记录。讨论中的备选方案保留为待定。
2. 作者表达了后续可复用的处理方法时，当轮将其写入本技能对应阶段，注明触发条件、具体做法及必要例外。无需作者额外说“记住”。对单篇论文的题目、数据集、特定结论和数值保留论文内记录；适用范围含糊时先按本篇执行，在范围会改变后续处理时再澄清。共享技能只保存可公开的通用方法，未发表材料及决策原话保留在论文内。
3. 复用现有规则并合并重复内容。作者改变决定时注明取代关系，检查并修订受影响的稿件、实验方案或回复；同步更新对应的通用规则。每阶段收尾时核对决策与产物，有新增时简要告知本篇采用了什么、技能新增或修订了什么。

## 选择并执行子技能

每行先执行主技能。箭头表示把上一项的实际输出交给下一项；括号注明追加调用的条件。项目内从 `.agents/skills/<名称>/SKILL.md` 读取已有技能。其他技能先查已安装目录；用内置检索机制或[固定版本索引](references/sources.md)读取匹配版本及当前任务依赖的说明。引用核验、结果和回复均保留定位。

| 用户的目标或当前阶段 | 调用顺序 | 输入、交付和判断 |
|---|---|---|
| 找文献、写综述、定题前梳理 | `paper-lookup` → `literature-review`（整理书目再接 `citation-management`） | 检索记录 → 合法全文 → 比较方法、数据、结果、反例与局限的证据表。用于选题的研究按项目规则逐篇完成 `paper-add` 和 `corpus-audit`。综述按研究问题组织。 |
| 只核对引用或清理 BibTeX | `citation-management` | DOI、现有 .bib 或文内引用 → 出版元数据、重复/版本候选、待核项。保留已有引用键或同步更新全文。需要验证某句时再回到全文，记录页码、章节或图表。 |
| 确定主线、规划大纲 | `academic-writing-skills-zh-cn` → `scientific-writing` | 研究问题、既有证据和目标读者 → 主要贡献、各节作用、每项主张的支持材料和缺口。只要大纲时交付到此。 |
| 起草引言、方法、讨论或整篇初稿 | `scientific-writing`（段落结构、术语或衔接需细化时接 `academic-writing-skills-zh-cn`） | 从已核实的方法和结果写起，明确适用条件。再写讨论、引言、摘要。记录重要论断的来源，核查数字、术语与图表编号。 |
| 只润色、重组指定段落或处理中英稿 | `academic-writing-skills-zh-cn` | 以原段和必要上下文为输入；输出请求语言的修订稿。保留数字、专业术语、比较对象与主张强度，分开列出内容疑点。按要求保留修订痕迹。 |
| 整理实验结果、消融和图表 | `ai-research-writing-skill` → `scientific-writing`（确需补跑且任务包含实验时用 `experiment-runner`） | 读取本论文已验证的结果与划分。指标绑定 run ID、文件和行/列或计算式；核对单位、分母、指标方向和绝对/相对变化。输出可追溯的图表、图注和 Results。只有整体基线对比时，不归因于单个模块。 |
| 面向特定机器学习会议写作 | `ml-paper-writing`（结果取证用上一行） | 根据已确认的会议、年份、轨道及官方指南组织贡献、篇幅和匿名稿，核对当届模板。电力或机器人期刊稿按目标期刊规则走普通写作路径。 |
| 做内部审阅、返修或回复审稿人 | 项目内用 `paper-review-revise`；独立预审按需用 `peer-review`；逐条回复及跨文件对齐用 `academic-writing-skills-zh-cn` | 审阅交付带位置、证据和影响的问题清单。返修逐项对应原意见、回应、实际改动位置及证据；补实验转结果路径。保留未解决项，区分外部原始意见与 AI 内部意见。 |
| 选刊、格式检查、准备交付 | 选刊用 `journal-matcher`；已定目标直接用 `scientific-writing`（ML 会议用 `ml-paper-writing`） | 核对目标官方要求，检查引文、图表、声明、补充材料与稿件一致。依请求用 Word/PDF 工具渲染检查，或用现有 LaTeX 工具编译。不将“准备投稿材料”解释为提交授权。 |

## 交接与收尾

在论文工作区复用现有 `literature/`、`protocol/results.json`、`manuscript/paper.md`、`manuscript/claims.json` 和 `reviews/review.json`。以现有格式为准，子技能的示例文件按需对接，不建立第二份论文状态。在已确定项目内完成整个阶段后，更新该论文记录，执行 `python paper.py --paper <id> advance` 并处理检查结果；独立稿件按其原格式交付。

缺少某项依据时，只暂停依赖它的结论，完成其余内容并说明缺哪张表、哪段原文或哪项实验。服务不可用时优先采用本地副本；若仍缺子技能，按上表以可用工具完成能够验证的工作，并说明实际调用、替代步骤与待核项。未经读取或执行不得报告子技能已运行。
