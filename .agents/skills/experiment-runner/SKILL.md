# 实验执行与复现

每条命令带 `--paper <id>`，读取本论文方案、数据清单和预算。数据获取、代码、运行与结果均在该论文目录，禁止使用其他论文运行 ID。

1. 数据清单置于 `data/manifests/`，执行 `fetch <manifest>`。检查数据内容、形状、单位、缺失、重复及许可，不以 HTTP 200 或哈希匹配代替质量核验。受限来源不可得则换公开来源或调整选题。
2. 编写真实基线与方法，锁定依赖。研究代码放 `src/`，配置放 `configs/`，所有被执行文件及依赖锁进入 `sources`。数据划分和预处理不得泄漏测试集。
3. `run configs/<name>.json`。程序复制输入与源码、执行真实子进程、记录日志及指标。使用 `{output}` 输出目录，必须产生非空有限数值对象 `metrics.json`。模型、预测和图表可作为其他产物。
4. 检查指标是否合理、基线是否正确、实现是否对应方法。必要的领域测试不能由流水线冒烟测试代替。
5. `reproduce <run-id>` 重放归档输入与源码，比较预先确定的指标容差或全部输出哈希。若需随机容差，在原始配置中解释；禁止看到差异后扩大容差来制造通过。
6. 复跑仅证明执行重复性。正式研究另用干净依赖环境重跑配置，并依据领域需要重复种子、跨数据集验证或独立审查。固定 seed 不保证跨硬件逐位相同。
7. `export-run <run-id>` 明确导出可共享代码与数值记录；数据和原始日志不导出。随后 `github-plan`、`github-sync --message "..."`。导出内容也需要检查是否适合公开。

失败保留 `run.json`、stdout/stderr 和部分产物。超时终止执行进程树。预算限制次数、单次与累计时间；不要绕过预算自动付费。运行 PID 在清单内，发现中断的 running 状态先确认进程和输出，再恢复研究，不能改写成成功。

目录隔离不是安全沙箱。第一版针对受信任、经检查的本地 Python 代码；远程 GPU/调度器接入需按实际环境另行实现。不要声称仅保存参数就已验证复现。
